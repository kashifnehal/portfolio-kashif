## Scroll model

The bundle contains `IntersectionObserver` in a `trackVisibleCells` routine that toggles `in-view` on case image cells. Runtime polling showed progressive opacity/transform before final visibility, suggesting an additional animation controller or observer-driven animation. Exact root margin, threshold, scrub model, start/end boundaries, and frame function are `Not yet verified`.

No pinned section was established. Normal document-flow section positions remained; the fixed footer background and fixed open-project content are separate fixed layers.

## Desktop/mobile differences

- Requested 1440x900 was observed as CSS 1152x720 with DPR 1.25; hero background reached opacity 1 by about 2.5s and `main.loaded` by about 4s in the sampled run.
- Requested 390x844 was observed as CSS 312x675; page was loaded and full document height was present by about 500ms, with no desktop clip-path intermediate in sampled states.
- Awards marquee duration changes from 5s to 10s below 576px.
- Cases geometry changes materially on mobile, so reveal timing and boundaries must be recalculated.

## Priority

Essential: hero reveal, hero typography entrance, case image reveal, project open/scroll lock, hash navigation, and accessible focus/hover feedback. Decorative but high-impact: WebGL motion, marquees, line wipes, availability tooltip, and footer/parallax movement.

## Limitations

The minified bundle had no source maps exposed in this pass. Timing values are sampled checkpoints, not guaranteed authored durations. Hover and close/back behavior could not be isolated reliably because overlapping grid layers and five duplicate hidden controls confused browser targeting.
